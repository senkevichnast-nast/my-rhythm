# Мой ритм

Личный планер: https://senkevichnast-nast.github.io/my-rhythm/

Главная, неделя, привычки, английский, блог, здоровье и личные проекты. Один `index.html` с встроенными стилями, JavaScript, шрифтом Manrope и иллюстрацией попугайчика Семечки.

## Использование

На опубликованном сайте: ввести свою почту и подтвердить вход в том браузере, где планируется пользоваться кабинетом. Встроенный браузер почты и Яндекс хранят разные сессии. Скопировать адрес кнопки входа из письма и вставить в поле «Ссылка входа из письма» в планере, не открывая ссылку. Подтверждение сохранится в текущем браузере. Предусмотрен и ввод кода, если позже будет подключён собственный отправитель писем. Для одной учётной записи на всех устройствах использовать одну и ту же почту.

Вход сохраняется после перезагрузки и повторного открытия браузера. Новый браузер, явный выход, удаление данных сайта или отзыв сессии сервисом требуют подтверждения. Временные сетевые ошибки не удаляют сессию; при наличии локальной копии кабинет открывается без сети, затем возобновляет синхронизацию.

Данные хранятся в Supabase с разграничением по владельцу и локальной копией браузера. Изменения отправляются автоматически; другие устройства получают обновления при открытии и примерно каждые 12 секунд, пока страница открыта. В конфликте одной записи показывается выбор версий. Таймер работает отдельно на каждом устройстве; сохранённые минуты синхронизируются.

Локальный файл открывается двойным щелчком и работает без регистрации. Его данные отдельны от опубликованного сайта. Перенос: «Экспорт» в локальной версии → «Импорт» в опубликованной после входа. Импорт заменяет текущие записи и требует подтверждения в интерфейсе.

## Публикация и хранение

Самочувствие отмечается трижды в день: 00:00–11:00, 11:01–17:00 и 17:01–24:00 по местному времени устройства. После «Сохранить отметку» карточка скрывается до следующего периода. Вечерняя карточка включает итог дня. История, редактирование и средние оценки доступны в «Здоровье → История и оценки» за всё время, 30 или 7 дней.

Подробный опрос в «Здоровье → На сегодня» сохраняется кнопкой «Сохранить запись». Дату можно менять, прошлые записи открываются через «История».

На главной постоянно доступна карточка «Здоровье сегодня». В здоровье есть заметные переходы к опросу, истории оценок, тренировкам, меню и покупкам, циклу и симптомам. Меню предлагается из собственных рецептов и заполняет только пустые приёмы пищи. Календарь цикла, длина завершённых циклов и повторения симптомов строятся по введённым датам. Импорт данных из Flo автоматически не выполняется — предыдущие даты можно внести вручную.

Недельный план использует те же задачи, датированные задачи и подзадачи проектов, публикации и тренировки, что главная и календарь. Сегодняшняя колонка закреплена при прокрутке.

- GitHub Pages: ветка `main`, корень репозитория.
- `schema.sql`: таблица, правило чтения собственных записей и транзакционная функция сохранения с проверкой версии.
- Формат данных `schemaVersion: 4` сохраняет отметки по периодам, задачи с подзадачами и идеи с подидеями проектов. Функция сохранения не разрешает старой открытой версии сайта перезаписать новые поля: такую вкладку нужно обновить.
- В HTML находится только публичный publishable key. Ключ не даёт доступ к дневникам без пользовательского входа. Секретные ключи и записи дневника не публикуются в репозитории.
- Supabase Site URL настроен на опубликованный адрес. Используется стандартное письмо со ссылкой входа, без своего SMTP. Стандартная отправка ограничена адресами участников проекта и лимитами провайдера; для личного использования владельцем.
- На текущем бесплатном тарифе Supabase редактирование шаблонов требует собственного SMTP (либо тарифа Pro); это подтверждено в панели 22.11.2026. Платные услуги не включены. После подключения отправителя для писем с кодом применить `cloud/email-code-template.html` в шаблонах Authentication → Email → Magic Link и Confirm signup. Это отдельная настройка Supabase; загрузка HTML в GitHub не меняет шаблон писем. Текущая проверка пароля не используется, код подтверждается штатным Auth API. Резервный ввод ссылки принимает только HTTPS-ссылки входа своего проекта и не переходит по вставленному адресу.
- Бесплатный проект Supabase может приостанавливаться при длительном отсутствии активности. Возобновить его можно в Supabase Dashboard. Резервную копию дневника можно скачать кнопкой «Экспорт».

## Проверка

`node verify.cjs` проверяет форматы данных, импорт, даты, недельную нумерацию, таймер, циклы, группировку плана, новые поля здоровья и объединение изменений.

`node tests/auth-session.cjs` проверяет восстановление входа, повторное открытие, сетевые сбои, обновление токенов между вкладками, ввод кода и допустимость ссылок подтверждения.

Manrope: SIL Open Font License. Дневник цикла даёт календарную оценку и не является средством контрацепции или медицинской диагностики.

## Проекты

Каждый проект открывается на отдельном широком экране. Во вкладке «Задачи» можно добавлять, редактировать и удалять задачи и подзадачи. Галочка задачи отмечает все её подзадачи. Во вкладке «Идеи» — основная идея, идейный нарратив и подидеи со своими заметками. Число пунктов не ограничено интерфейсом; действуют общие ограничения объёма браузерного и облачного сохранения.

Прогресс считается по конечным шагам: подзадачам и задачам без подзадач. Родитель не считается второй раз. На карточке и внутри проекта показаны «сделано из всего» и процент. Добавление нового незавершённого шага пересчитывает процент. Идеи в прогресс задач не входят.

Прежние названия, описания, даты и заметки проектов сохраняются. Старый «следующий шаг» становится первой задачей, старый вручную заданный процент остаётся в данных; новый видимый прогресс рассчитывается по галочкам. Защита save_planner не позволяет старым вкладкам перезаписать новую структуру. После обновления следует перезагрузить открытый планер на других устройствах.

`node tests/projects.cjs`: перенос старых проектов, вложенный CRUD, прогресс, экспорт/импорт, объединение изменений двух устройств и экранирование текста.

У каждой задачи и подзадачи проекта есть необязательная дата. Датированные пункты видны в главной, неделе и календаре, без копирования записей. У родителя и подзадач независимые даты; каждый явно запланированный пункт отображается в свой день. Галочки и редактирование общие для всех экранов. Завершение родителя отмечает все подзадачи; завершение всех подзадач завершает родителя. Перенос меняет дату исходного пункта, очистка даты убирает его из плана и сохраняет в проекте. Старые задачи проектов остаются без назначенной даты.

Задачи проекта можно свернуть нажатием на заголовок со стрелкой. Название, дата, галочка и счётчик подзадач остаются видны. «Свернуть все» / «Развернуть все» меняют вид списка целиком. Выбранный вид запоминается в этом браузере отдельно для каждой учётной записи; записи и прогресс при сворачивании не меняются.

## Повторение задач

В создании и редактировании обычной задачи, задачи проекта или подзадачи есть поле «Повторение»: каждый день, по выбранным дням недели или каждый месяц. Интервал задаёт шаг расписания; необязательная дата окончания включается в него. Дата задачи служит началом расписания. Для 29–31 числа в коротком месяце используется последний день; в следующем месяце исходное число восстанавливается.

Повторы рассчитываются для нужного дня без создания бесконечных копий. У каждого — собственная галочка, перенос и пропуск. Перенос одного повтора не сдвигает серию. В истории настроек видны сохранённые отметки, переносы и пропуски; пропущенный повтор можно вернуть. Изменение или отключение расписания сохраняет записанную историю. Удаление всей задачи удаляет и её историю после подтверждения.

Подзадачи без своего расписания повторяются вместе с родителем; собственное расписание подзадачи независимо. В проекте можно выбрать дату отметок. Прогресс повторяющихся шагов относится к выбранному дню, разовые шаги сохраняют общий статус. Если после переноса в один день попало несколько повторов, у задачи появляется выбор «Повтор от». Галочки в проекте, дне и неделе используют одну запись. Данные версии 5 включают расписания и историю; прежние данные автоматически дополняются без изменения старых отметок. Существующая серверная защита от понижения версии предотвращает перезапись старой вкладкой.

## Свои разделы

Кнопка «Новый раздел» есть в меню и в окне задачи. Название, эмодзи и описание редактируются в настройках раздела. Раздел появляется отдельной вкладкой, группой в общем плане, вариантом выбора в задаче и таймере фокуса. На своей вкладке показаны план выбранного дня и все задачи раздела, включая повторяющиеся. При удалении раздела его задачи и записи фокуса остаются в «Без раздела». На телефоне нижнее меню можно прокручивать горизонтально.

`node tests/recurrence.cjs` проверяет интервалы, дни недели, конец месяца, независимые отметки, переносы и пропуски, наследование расписаний, совпавшие повторы, миграцию, объединение правок устройств и жизненный цикл своих разделов.
